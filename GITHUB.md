# Публикация меню на GitHub Pages

Подробная инструкция: от пустого аккаунта до работающей ссылки и QR на столах.
Сайт статический, серверы и базы данных не нужны — GitHub просто раздаёт файлы.

---

## 0. Что понадобится

- Аккаунт GitHub (бесплатный).
- Папка `site/` из этого проекта (или архив `hookahplace-menu-site.zip`).
- 10–15 минут.

Важно: бесплатный GitHub Pages работает **только в публичных репозиториях**.
Код меню всё равно виден любому, кто откроет репозиторий — это нормально для
лендинга: там нет ничего, кроме цен и текста меню.

Если аккаунта нет: [github.com/signup](https://github.com/signup) → почта → пароль →
имя пользователя → подтвердить e-mail. GitHub может попросить включить двухфакторную
аутентификацию (2FA) — это обязательное требование, включите через приложение-аутентификатор
или SMS.

---

## 1. Создать репозиторий

1. Откройте [github.com/new](https://github.com/new).
2. **Repository name**: `hookahplace-menu` (латиницей, без пробелов — от этого зависит адрес сайта).
3. **Description**: `HookahPlace e-menu` — необязательно.
4. Выберите **Public**.
5. **Add a README file** — можно не ставить галочку: свой README уже лежит в папке.
6. Нажмите **Create repository**.

После создания вы увидите пустую страницу с подсказками — это нормально.

---

## 2. Загрузить файлы (самый простой путь — через браузер)

1. На странице репозитория нажмите **Add file ▾** (рядом с зелёной кнопкой *Code*)
   → **Upload files**.
2. Откройте папку `site/` в Finder.
3. Выделите **всё содержимое** папки: `index.html`, `presentation.html`, `menu-b.html`,
   `menu-c.html`, `qr-print.html`, `README.md`, папку `assets`, файл `.nojekyll`
   (скрытый — включается `Cmd + Shift + .`).
   Затем перетащите выделенное в область загрузки на странице GitHub.

   > **Главная ошибка:** перетащить саму папку `site`. Тогда файлы окажутся
   > по адресу `/site/index.html`, и корень сайта будет пустым (404).
   > Нужно перетаскивать **содержимое** папки, а не её саму.

4. Дождитесь, пока все файлы появятся в списке (88 файлов, около 2,4 МБ).
5. Внизу в поле **Commit changes** напишите `HookahPlace e-menu` и нажмите
   **Commit changes**.

Проверка: на главной странице репозитория должен быть `index.html`, папка `assets`
и остальные файлы — но **не** папка `site`.

### Если `.nojekyll` не загрузился

Браузеры часто пропускают файлы, начинающиеся с точки. Это не критично: в проекте
нет папок с подчёркиванием, которые Jekyll бы проигнорировал, сайт соберётся и так.
Но если хотите добавить:

**Add file ▾ → Create new file** → в поле имени введите `.nojekyll` → в поле содержимого
поставьте один перевод строки → **Commit changes**.

---

## 3. Включить GitHub Pages

1. В репозитории: **Settings** (верхнее меню, не путать с настройками аккаунта).
2. В левом меню: **Pages**.
3. Блок **Build and deployment**:
   - **Source**: `Deploy from a branch`;
   - **Branch**: `main`, папка `/ (root)`;
   - **Save**.
4. Через 1–2 минуты обновите страницу — сверху появится
   «Your site is live at `https://USERNAME.github.io/hookahplace-menu/`»
   и кнопка **Visit site**.

Если через 5 минут адреса нет: вкладка **Actions** → должен идти или завершиться
workflow `pages build and deployment`. Красный крестик — откройте лог, чаще всего
это неверная папка в настройках Pages.

---

## 4. Проверить сайт

Откройте ссылку на телефоне (не на компьютере — важно увидеть реальные шрифты и жесты):

- [ ] меню открывается, обложка «МЕНЮ» на винных волнах;
- [ ] переключатель **RU / EN** в шапке работает, текст меняется целиком;
- [ ] якоря навигации (01 Авторские, 02 Чай…) прокручивают к разделам;
- [ ] «Состав +» раскрывается;
- [ ] в подвале — адрес, два телефона, часы, Instagram, карта;
- [ ] QR в подвале ведёт на этот же адрес;
- [ ] `…/presentation.html` открывается и показывает превью;
- [ ] `…/qr-print.html` печатается на A4 без обрезки.

Адрес английской версии: `…/?lang=en`.

---

## 5. Свой домен (по желанию)

1. **Settings → Pages → Custom domain** → `menu.hookahplace.ru` → **Save**.
   GitHub создаст в репозитории файл `CNAME` — удалять его нельзя.
2. У регистратора домена (reg.ru, timeweb и т. п.) добавьте запись:
   - тип **CNAME**
   - имя/хост **menu**
   - значение **USERNAME.github.io**
3. Подождите от 5 минут до нескольких часов (DNS).
4. Когда в Pages появится «DNS check successful», включите **Enforce HTTPS**.

После смены адреса **QR нужно перевыпустить**: откройте `qr-print.html` уже на новом
домене, скачайте лист и замените наклейки. Старый QR ведёт на старый адрес.

---

## 6. Как обновлять меню потом

**Через браузер (без программ):**
1. Откройте `assets/js/data.js` в репозитории.
2. Нажмите карандаш ✏️ (Edit this file).
3. Поправьте цену, например `price: 800` → `price: 850`.
4. **Commit changes** → через минуту сайт обновится.

То же для `data-en.js` (английская версия) и блока `venue` (адрес, телефоны, часы).

**Через компьютер:** клонируйте репозиторий, правьте файлы, `git commit` + `git push`.

## 7. Вариант через GitHub Desktop

Если не хочется работать в браузере:

1. Установите [GitHub Desktop](https://desktop.github.com), войдите в аккаунт.
2. **File → New repository** → имя `hookahplace-menu`, локальная папка, **Create**.
3. Скопируйте **содержимое** `site/` в созданную папку (не саму папку).
4. В GitHub Desktop появится список файлов → внизу поле Summary → `HookahPlace e-menu`
   → **Commit to main**.
5. Кнопка **Publish repository** (сверху) → снимите галочку *Keep this code private*
   → **Publish**.
6. Дальше — раздел 3 (включить Pages в настройках).

## 8. Вариант через командную строку

```bash
cd путь/к/site
git init
git add .
git commit -m "HookahPlace e-menu"
git branch -M main
git remote add origin https://github.com/USERNAME/hookahplace-menu.git
git push -u origin main
```

Пароль от аккаунта при push **не подойдёт** — нужен Personal Access Token:
GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)**
→ Generate new token → срок и право **repo** → скопировать токен и вставить вместо пароля.

Или через GitHub CLI: `brew install gh`, `gh auth login`, затем `gh repo create`.

## 9. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `404` на главной | загрузили папку `site` целиком | файл `index.html` должен лежать в корне репозитория |
| Страница без стилей, «голый» текст | не загрузилась папка `assets` | загрузите `assets` рядом с `index.html` |
| Сайт открылся, но старый | кэш браузера / Pages ещё собирается | подождите 2 минуты, обновите с `Cmd + Shift + R` |
| В настройках Pages нет ветки `main` | репозиторий пустой или ветка `master` | загрузите файлы, выберите существующую ветку |
| Pages не собирается | Source указан неверно | Settings → Pages → Deploy from a branch → `/(root)` |
| QR ведёт на старый адрес | наклейки напечатаны до смены домена | перевыпустите QR на новом домене |
| Шрифты не такие, как в макете | браузер не загрузил woff2 | проверьте, что папка `assets/fonts` на месте |

## 10. Чек-лист после публикации

- [ ] Сайт открывается по HTTPS (`https://`, замок в адресной строке).
- [ ] RU и EN работают, `?lang=en` открывает английскую версию.
- [ ] Телефоны в подвале звонят по тапу.
- [ ] QR из подвала сканируется с iPhone и Android.
- [ ] `qr-print.html` напечатан на A4 в масштабе 100%, QR читается камерой.
- [ ] Ссылка добавлена в шапку Instagram и в карточку на картах.
- [ ] Презентация `presentation.html` закрыта от поиска (`noindex`) — проверить не обязательно.
- [ ] В репозитории осталось понятное имя и описание, чтобы не потерять доступ.
