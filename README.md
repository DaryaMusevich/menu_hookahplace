# Электронное меню HookahPlace

Прототипы электронного меню на основе печатного макета 170×242 мм (12 страниц).
Три визуальных направления, одинаковый контент, готовая страница-презентация и QR-пакет.

## Готово к публикации

Папка `site/` — это самостоятельный сайт для загрузки в репозиторий GitHub:

```
site/
├── index.html           меню (RU/EN) — корень сайта, сюда ведёт QR
├── presentation.html    презентация концепции (noindex)
├── menu-b.html          альтернативные варианты
├── menu-c.html
├── qr-print.html        лист QR для печати
├── assets/              стили, данные, шрифты, иллюстрации
├── .nojekyll
├── README.md            краткая инструкция
└── GITHUB.md            подробная публикация на GitHub Pages
```

Тот же архив: `hookahplace-menu-site.zip` (2 МБ). Подробная инструкция по публикации
(аккаунт, репозиторий, Pages, домен, обновления, частые ошибки) — [GITHUB.md](menu-qr/GITHUB.md).
Загружать нужно **содержимое** `site/`, а не саму папку.

## Что открыть

| Файл | Что это |
|---|---|
| `index.html` | **Презентация**: концепция, три варианта, размещение, QR, план запуска |
| `menu-a.html` | **Вариант A «Тихий сад»** — выбранный: продолжение печатного меню, RU + EN |
| `menu-b.html` | Вариант B «Ночь» — тёмный лаунж, поиск, калькулятор кальянов |
| `menu-c.html` | Вариант C «Витрина» — светлый каталог с плитками под фото |
| `qr-print.html` | Лист A4 с 8 QR-карточками для столов (печать из браузера) |

Открывать лучше через локальный сервер (иначе часть браузеров ограничивает `file://`):

```bash
cd menu-qr
python3 -m http.server 8000
# затем http://localhost:8000
```

```
│   │   ├── data-en.js    ← то же самое по-английски (та же структура)
│   │   ├── ui.js         шторка, поиск, тосты, QR, reveal

```

## Как править меню

Все цены и тексты лежат в `assets/js/data.js`. Пример:

```js
{ name: "Глинтвейн", price: 800, vol: "800 мл", desc: "…", comp: "…" }
```

Два объёма у одной позиции:

```js
{ name: "Вишнёвый пуэр", price: 750, vol: "800 мл",
  variants: [{ vol: "800 мл", price: 750 }, { vol: "1 200 мл", price: 1050 }] }
```

Одна правка обновляет все три варианта, поиск и шторки с составом.

## Два языка (вариант A)

В шапке меню — переключатель **RU / EN**. Переводится всё: обложка, разделы,
названия позиций, описания, составы, правила и подписи в футере.

- перевод лежит в `assets/js/data-en.js` — структура повторяет `data.js`,
  порядок позиций должен совпадать;
- выбор языка запоминается в браузере гостя (`localStorage`);
- ссылка сразу на английскую версию: `menu-a.html?lang=en`;
- перевод черновой и требует вычитки носителем языка (особенно названия
  чаёв: «1001 Nights», «Taiga blend», «Count Orlov» — можно уточнить у поставщика).

## Чаевые

Блок «Чаевые» стоит после раздела «Перекус» и перед правилами: заголовок, короткий текст
и кнопка «Оставить чаевые», которая открывает страницу Netmonet в новой вкладке.
Никакого QR — гость читает меню с того же телефона, поэтому работает именно кнопка.

Тексты и ссылка задаются в `tips` (`data.js` / `data-en.js`). Ссылка на группу Netmonet —
`https://netmonet.co/tip/group/680420?o=4`.

## Контакты заведения

Задаются в `venue` внутри `data.js` и `data-en.js`:

```js
address: "г. Ноябрьск, ул. Советская, 31а",
phones: [{ label: "+7 961 559-04-97", href: "tel:+79615590497" }, …],
instagram: "https://www.instagram.com/hookahplace.nsk…",
hours: ""   // пусто — строка со временем работы не выводится
```

## Как опубликовать

**Вариант 1 — за 5 минут, бесплатно.** Открыть [app.netlify.com/drop](https://app.netlify.com/drop),
перетащить папку `menu-qr` целиком. Получите адрес вида `hookahplace-menu.netlify.app`.
Дальше в настройках домена привязать `menu.hookahplace.ru` (CNAME на Netlify).

**Вариант 2 — GitHub Pages.** Создать репозиторий, загрузить папку, включить
Settings → Pages → Deploy from branch. Адрес `username.github.io/repo`.

**Вариант 3 — свой хостинг.** Залить папку в `public_html/menu/`. Нужен только HTTPS
(обычно включён) — без него камера телефона не откроет ссылку из некоторых приложений.

После публикации: открыть `index.html` на новом адресе — QR в разделе «QR-пакет»
и лист `qr-print.html` пересчитаются на этот адрес автоматически.

## QR: что важно при печати

- минимум 25×25 мм, на подставке — 35–45 мм;
- тихая зона не меньше 4 модулей, не обрезать;
- тёмный код на светлом фоне, без инверсии;
- матовая ламинация (глянец и изгиб ловят блики);
- один QR на **всё** меню, а не на отдельные разделы;
- адрес короткий и постоянный — при смене адреса придётся перепечатать носители;
- проверить сканирование с iPhone, Android и со «старой» камерой.

## Что нужно доделать перед запуском

- [ ] Сверить цены, граммовки и составы с текущим меню (перенесены с печатного)
- [x] Часы работы внесены: Вс–Чт 12:00–01:00, Пт–Сб 12:00–03:00
- [ ] Вычитать английский перевод с носителем языка
- [ ] Решить, нужны ли фотографии (в варианте C плитки готовы их принять)
- [ ] Проверить отображение на реальных телефонах (iOS Safari, Android Chrome)
- [ ] Привязать домен и перевыпустить QR
- [ ] Напечатать носители: подставки на столы, табличка на вход, QR в чек

## Технические заметки

- Без сборки и зависимостей: чистые HTML/CSS/JS, шрифты и картинки локальные.
- Нет внешних запросов — работает и без интернета после загрузки из кэша.
- Данные не отправляются на сервер: корзины и оплаты нет, это витрина.
- Иллюстрации вырезаны из предоставленного PDF (400 dpi, прозрачный фон),
  волновой паттерн сгенерирован по мотивам обложки.
- Прототип не подключён к кассе. Для стоп-листов и синхронизации с iiko/r_keeper
  нужен сервис меню (Quick Resto, Menu.ru) — см. раздел «Размещение» в презентации.
- Вариант A не зависит от шрифтов Google: файлы woff2 лежат в `assets/fonts`.
  Английские и русские глифы включены в набор, поэтому переключение языка
  не вызывает подгрузки сети.
